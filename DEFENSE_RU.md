# Разбор Assignment 4 для защиты

## Что делает проект

Это три учебные страницы: простые HTML-формы, контактная форма Bootstrap и форма регистрации студенческого клуба. Четвёртая страница `complete.html` — результат демонстрационной отправки. Здесь нет JavaScript, сервера и базы данных.

Открывай страницы в порядке **HTML forms → Bootstrap forms → Registration**. Так видно, как одна идея постепенно дополняется проверкой данных и оформлением.

## Что объяснять в начале каждого HTML-файла

- `<!DOCTYPE html>` включает современный режим HTML.
- `<html lang="en">` указывает язык интерфейса.
- `<meta charset="UTF-8">` задаёт кодировку.
- `viewport` позволяет мобильному браузеру использовать ширину устройства.
- `<title>` задаёт название вкладки.
- `<link rel="stylesheet">` подключает CSS. В двух страницах Bootstrap подключён раньше `styles.css`, чтобы собственные правила могли уточнять оформление.
- `<main>`, `<header>`, `<nav>`, `<section>`, `<footer>` обозначают смысловые части страницы.
- Ссылки `href` открывают соседние HTML-файлы. `aria-current="page"` обозначает текущую страницу; CSS выделяет её ссылку.

## basic.html — задачи 0 и 1

В задаче 0 у формы есть имя, email, сообщение и кнопка. Например:

```html
<label for="basic-name">Name</label>
<input id="basic-name" name="name" type="text">
```

`for` связывает подпись с `id` поля. При нажатии на подпись поле получает фокус. `id` должен быть уникальным на странице. `name` — имя значения при отправке формы. `type` выбирает вид поля.

`textarea` предназначен для нескольких строк, `rows` задаёт его начальную высоту. `button type="submit"` запускает отправку.

В задаче 1 структура та же, но добавлены ограничения:

| Атрибут | Значение |
| --- | --- |
| `required` | Пустое поле не допускается |
| `type="email"` | Проверка синтаксиса email; существование адреса не проверяется |
| `minlength="2"` | Минимум 2 символа |
| `maxlength="30"` | Максимум 30 символов |

Браузер сам проверяет эти атрибуты. При ошибке он останавливает отправку и показывает подсказку. JavaScript для этого не нужен. В задаче 0 поля необязательные, но непустой email всё равно проверяется благодаря своему типу.

## bootstrap.html — задачи 2 и 3

Bootstrap — готовый набор CSS-классов. Подключена только таблица стилей; Bootstrap JavaScript в проекте отсутствует.

| Класс | Что делает |
| --- | --- |
| `container` | Ограничивает ширину и задаёт внешние отступы |
| `row` | Создаёт строку сетки |
| `g-3` | Добавляет промежутки между колонками |
| `col-md-6` | От 768px занимает 6 из 12 колонок, то есть половину строки |
| `col-12` | Занимает всю строку |
| `form-label` | Оформляет подпись |
| `form-control` | Оформляет текстовое поле и textarea |
| `form-select` | Оформляет выпадающий список |
| `form-text` | Делает небольшой поясняющий текст |
| `btn btn-primary` | Оформляет основную кнопку |
| `valid-feedback` / `invalid-feedback` | Оформляет сообщения об успехе и ошибке |

`placeholder` — пример внутри пустого поля. Он не заменяет подпись и не считается введённым значением. `aria-describedby` связывает поле с пояснением или сообщением об ошибке.

### Как валидация работает без JavaScript

У формы сразу указан класс `was-validated`. Браузер определяет состояния `:valid` и `:invalid` по HTML-атрибутам. Встроенные CSS-правила Bootstrap используют эти состояния, меняют рамку поля и показывают нужное сообщение.

Из-за постоянного `was-validated` красные рамки видны сразу. При правильном вводе они становятся зелёными. `novalidate` не используется: браузер продолжает блокировать неверную отправку.

Ниже находятся отдельные примеры `is-valid` и `is-invalid`. Это классы **фиксированного оформления**, они сами не проверяют введённые данные. Поэтому примеры сделаны `readonly`. Рабочую проверку демонстрируй в контактной форме над ними.

## index.html — задача 4

Форма регистрации использует ту же сетку и проверку, поэтому новую логику изучать не нужно.

- `type="password"` скрывает символы при отображении. Это не шифрование.
- `minlength="8"` и `maxlength="30"` ограничивают длину пароля.
- `autocomplete="new-password"` сообщает браузеру, что поле предназначено для нового пароля.
- Радиокнопки `type="radio"` имеют одинаковый `name="gender"`. Поэтому можно выбрать только один вариант. `required` делает выбор обязательным.
- Флажки `type="checkbox"` можно выбирать независимо друг от друга. Хобби необязательны; каждое имеет своё `value`.
- `fieldset` объединяет связанные варианты, а `legend` задаёт название группы.
- `select` создаёт список стран, `option` — варианты. Первый вариант имеет пустое `value`, поэтому `required` требует выбрать страну.
- `type="reset"` возвращает исходные значения полей. В нашем случае поля становятся пустыми, а выбранные варианты сбрасываются.
- `d-flex gap-2` размещает две кнопки рядом с промежутком; `fw-normal` делает слово “optional” обычной толщины.

**Ограничение подтверждения пароля:** HTML проверяет длину двух полей по отдельности. Сравнить одно поле с другим без программной логики он не может. Поэтому нельзя говорить, что проект автоматически проверяет совпадение. Сообщение “Length is valid” означает только подходящую длину. DOM и обработчики событий относятся к более поздним неделям.

## styles.css — собственное оформление

Файл небольшой: основные правила задают цвет фона, шрифт, ширину страницы, отступы, рамки и оформление навигации.

- `box-sizing: border-box` включает padding и border в заданную ширину элемента.
- `.page` — селектор класса. `max-width: 900px` ограничивает ширину; `margin: auto` центрирует блок.
- `padding` — внутренний отступ; `margin` — внешний.
- `display: flex`, `gap` и `flex-wrap: wrap` располагают ссылки рядом и переносят их, если места недостаточно.
- `nav a[aria-current="page"]` выбирает текущую ссылку по атрибуту.
- `.basic input, .basic textarea` оформляет только поля внутри элемента с классом `basic`.
- `width: 100%` растягивает поля на ширину доступного блока.
- `resize: vertical` разрешает менять высоту textarea, сохраняя ширину страницы.

Адаптивные колонки на страницах Bootstrap обеспечивает `col-md-6`: на маленьком экране поля идут друг под другом. Писать свои медиазапросы для этих колонок не нужно.

## Что происходит при Submit

`action="complete.html"` задаёт страницу назначения, `method="get"` помещает именованные значения в адрес. Сначала браузер проверяет ограничения; при ошибке перехода нет.

У паролей специально нет `name`, поэтому они не попадают в URL. В настоящей регистрации нужны сервер, HTTPS и подходящий способ обработки данных. Здесь нет реального создания аккаунта или отправки письма; страница результата прямо об этом говорит.

## Показ на защите за 3–5 минут

1. На первой странице покажи подписи и три поля в задаче 0.
2. В задаче 1 нажми Submit с пустыми полями. Затем введи неправильный email и слишком короткое сообщение.
3. На Bootstrap-странице введи корректные данные. Покажи, как меняются рамки и сообщения. Объясни отличие `was-validated` от фиксированных классов в примерах.
4. На регистрации покажи короткий пароль, выбор одного пола и нескольких хобби. Затем проверь Reset.
5. Заполни поля тестовыми значениями и отправь форму. Объясни, почему это демонстрационная страница, а не реальный аккаунт.
6. Сузь окно: две колонки станут одной. Объясни `col-md-6` и сетку из 12 колонок.
